# ソリューション案C: インシデント報告＆セキュリティ文化醸成プラットフォーム

## 1. 概要

### コンセプト

セキュリティ文化の醸成を主軸に、「報告しやすい環境づくり」「脅威情報の日常的な共有」「従業員の当事者意識の向上」を実現する社内プラットフォーム。技術的なセキュリティ対策ではなく、**組織の「人」と「文化」を変える**ことにフォーカスする。

### 基本思想

> 「セキュリティは全員の責任」を掛け声で終わらせず、日常的な行動として根付かせる仕組みを提供する

- **心理的安全性ファースト**: 報告・相談のハードルを徹底的に下げる
- **情報の民主化**: セキュリティ情報を一部の専門家だけでなく全従業員に届ける
- **可視化による経営参画**: ダッシュボードで経営層のコミットメントを引き出す
- **分散型リーダーシップ**: セキュリティチャンピオン制度で各部門に推進力を持たせる

### 対象Gap

| 課題ID | 課題名 | 対応度 |
|--------|--------|--------|
| GAP-C1 | 報告忌避文化→心理的安全性ベースの報告文化 | ◎ 直接解決 |
| GAP-H3 | インシデント報告行動の欠如 | ◎ 直接解決 |
| GAP-C2 | 「IT部門任せ」→「全員の責任」意識 | ◎ 直接解決 |
| GAP-C3 | セキュリティ文化醸成施策の不在 | ◎ 直接解決 |
| GAP-O2 | 経営層コミットメント不足 | ○ 部分解決（ダッシュボードによる可視化） |
| GAP-E1 | 最新脅威への対応遅延 | ○ 部分解決（脅威情報フィード） |
| GAP-O4 | ポリシーの形骸化 | △ 間接的に寄与（情報共有・浸透） |

## 2. 主要機能

### 2.1 ワンクリックインシデント報告機能

**目的**: インシデント報告の心理的・物理的ハードルを極限まで下げる

#### 機能詳細

| 機能 | 説明 |
|------|------|
| **ワンクリック報告** | メールクライアント連携の報告ボタン（Outlook/Gmail アドイン）。不審メールをワンクリックで報告 |
| **Web報告フォーム** | カテゴリ選択式の簡易報告フォーム（不審メール/不審な電話/物理セキュリティ/データ関連/その他） |
| **匿名報告オプション** | 実名/匿名を選択可能。匿名でも報告内容は適切にトリアージされる |
| **報告テンプレート** | よくある報告パターンのテンプレート。記入の負担を最小化 |
| **自動トリアージ** | AI/ルールベースで報告の緊急度を自動分類（Critical/High/Medium/Low/Info） |
| **報告者フィードバック** | 報告後に「ありがとうございます」メッセージ + 報告内容の対応状況を後日通知 |
| **報告統計** | 月次の報告件数・傾向をチームごとに可視化（ランキングではなく参加率として表示） |

#### ユーザーフロー

```
不審メール発見 → 報告ボタンクリック → カテゴリ選択（任意）
    → 補足コメント入力（任意） → 送信 → 感謝メッセージ表示
    → セキュリティチームに自動転送 → トリアージ
    → 報告者に対応結果フィードバック
```

### 2.2 セキュリティニュース・脅威情報フィード

**目的**: 最新の脅威情報を全従業員に日常的に届け、セキュリティへの関心を維持する

#### 機能詳細

| 機能 | 説明 |
|------|------|
| **脅威ニュースフィード** | 外部ソース（IPA、JPCERT/CC、NISC等）からの脅威情報を自動収集・要約して配信 |
| **社内セキュリティ通信** | セキュリティチームが作成する社内向けの平易な解説記事 |
| **パーソナライズ配信** | 部門・役割に応じた関連度の高い情報を優先表示 |
| **週次ダイジェスト** | 1週間の重要トピックをメール/Slack/Teams通知でダイジェスト配信 |
| **緊急アラート** | 重大な脅威発生時のプッシュ通知（例: 大規模フィッシングキャンペーン検知時） |
| **「これ知ってた？」クイズ** | ニュース記事に紐づく1問クイズで理解度を確認（ゲーミフィケーション要素） |

#### コンテンツソース

- **自動収集**: IPA、JPCERT/CC、NISC、US-CERT、各ベンダーブログのRSS/API
- **AI要約**: 技術的な情報を非技術者向けに平易に要約（社内LLM活用）
- **手動作成**: セキュリティチームによる社内事例解説、ポリシー解説

### 2.3 匿名相談・Q&A機能

**目的**: セキュリティに関する疑問や不安を気軽に相談できる場を提供する

#### 機能詳細

| 機能 | 説明 |
|------|------|
| **匿名Q&A掲示板** | セキュリティに関する質問を匿名で投稿可能。セキュリティチームや他の従業員が回答 |
| **AIチャットボット** | よくある質問（パスワードリセット、VPN接続、データ分類等）に即時回答 |
| **カテゴリ別FAQ** | 蓄積されたQ&Aをカテゴリ別に整理し、ナレッジベースとして活用 |
| **投票機能** | 有用な質問・回答に「いいね」を付けて優先表示 |
| **エスカレーション** | AIで解決できない質問は自動的にセキュリティチームにエスカレーション |
| **プライベート相談** | 機密性の高い相談（内部不正の疑い等）は1対1の非公開チャネルで対応 |

### 2.4 セキュリティチャンピオン制度管理

**目的**: 各部門にセキュリティ推進者を配置し、分散型のセキュリティリーダーシップを確立する

#### 機能詳細

| 機能 | 説明 |
|------|------|
| **チャンピオン登録・プロフィール** | 各部門のセキュリティチャンピオンの登録・公開プロフィール |
| **専用トレーニングパス** | チャンピオン向けの高度なセキュリティ研修コンテンツ |
| **活動ログ** | チャンピオンの活動記録（部門内勉強会開催、報告促進、質問回答等） |
| **コミュニティ機能** | チャンピオン同士の情報共有・ディスカッションフォーラム |
| **表彰・バッジシステム** | 活動実績に基づくバッジ付与、四半期MVCチャンピオン表彰 |
| **部門別スコアカード** | チャンピオンの活動と部門のセキュリティ指標の関連を可視化 |

#### チャンピオン制度の運用

```
選出（各部門1〜2名） → 基礎研修（オンライン2時間）
    → 月次ミーティング（チャンピオン同士 + セキュリティチーム）
    → 部門内活動（勉強会、報告促進、相談対応）
    → 四半期レビュー → 表彰 → スキルアップ研修
```

### 2.5 経営層向けダッシュボード

**目的**: セキュリティ文化の状態を可視化し、経営層のコミットメントと意思決定を支援する

#### ダッシュボード構成

| パネル | 表示内容 |
|--------|---------|
| **ヒューマンリスクスコア** | 組織全体の人的セキュリティリスクを0-100でスコアリング |
| **報告活動サマリー** | 月次報告件数推移、報告までの平均時間、カテゴリ別内訳 |
| **エンゲージメント指標** | ニュースフィード閲覧率、Q&A活用率、チャンピオン活動率 |
| **部門別比較** | 部門ごとの報告率・エンゲージメントの比較（ヒートマップ） |
| **トレンド分析** | 報告内容のトレンド、増加している脅威カテゴリの可視化 |
| **ROI指標** | インシデント検知時間の短縮、報告率向上による推定コスト削減額 |
| **ベンチマーク** | SANS成熟度レベルの現在位置、業界平均との比較 |

#### レポート機能

- **月次レポート自動生成**: 経営会議向けのPDF/PPTレポートを自動生成
- **アラート通知**: KPIが閾値を下回った場合の自動アラート
- **ドリルダウン**: 全社→部門→チームレベルへの詳細分析

### 3.2 技術スタック

| レイヤー | 技術 | 選定理由 |
|---------|------|---------|
| **フロントエンド** | Next.js (React) + TypeScript | SSR/SSG対応、高速な画面遷移、社内開発者の習熟度が高い |
| **UIライブラリ** | Tailwind CSS + shadcn/ui | 高品質UIを迅速に構築、カスタマイズ性が高い |
| **バックエンド** | Next.js API Routes + Node.js | フロントエンドと統一スタック、サーバーレス対応 |
| **データベース** | PostgreSQL | 信頼性、JSON対応、全文検索 |
| **ORM** | Prisma | 型安全なDB操作、マイグレーション管理 |
| **キャッシュ** | Redis | セッション管理、リアルタイム通知、ランキング集計 |
| **認証** | NextAuth.js + SAML/OIDC | 社内SSO（Azure AD/Okta等）との連携 |
| **AI/LLM** | Claude API / Azure OpenAI | ニュース要約、チャットボット、報告トリアージ |
| **通知** | Slack API / Microsoft Graph API | 既存コミュニケーションツールとの統合 |
| **ファイルストレージ** | AWS S3 / Azure Blob | 添付ファイル、レポートPDF保存 |
| **ホスティング** | Vercel / AWS / Azure | 社内インフラポリシーに応じて選択 |
| **監視** | Datadog / Sentry | アプリケーション監視、エラー追跡 |
| **CI/CD** | GitHub Actions | 自動テスト・デプロイ |

### 3.3 セキュリティ要件

- **認証**: 社内SSO必須（SAML 2.0 / OIDC）
- **認可**: RBAC（管理者/セキュリティチーム/チャンピオン/一般従業員）
- **通信暗号化**: TLS 1.3
- **データ暗号化**: AES-256（保存時）、匿名報告データの特別保護
- **監査ログ**: 全操作の監査ログ記録（匿名報告のプライバシーを保護しつつ）
- **データ保持**: 報告データ3年保持、匿名性担保のためのデータ分離設計

## 4. メリット・デメリット

### 4.1 メリット

| カテゴリ | メリット |
|---------|---------|
| **文化変革** | 報告文化の醸成、心理的安全性の向上という最も根本的な課題（GAP-C1）に直接アプローチ |
| **即効性** | ワンクリック報告はすぐに効果が現れる。報告件数の増加は短期間で測定可能 |
| **低い導入障壁** | 「学習を強制する」のではなく「報告・相談しやすくする」アプローチのため、従業員の抵抗感が低い |
| **経営層の可視化** | ダッシュボードにより経営層がセキュリティ状況を把握でき、コミットメント向上（GAP-O2）に寄与 |
| **スケーラビリティ** | チャンピオン制度により、セキュリティチームの負荷を分散しつつ全社展開可能 |
| **データ駆動** | 報告データ・エンゲージメントデータの蓄積により、リスクの定量的把握と改善が可能 |
| **持続的効果** | 文化が根付けば、個別のトレーニング以上に持続的なセキュリティ向上効果 |

### 4.2 デメリット

| カテゴリ | デメリット |
|---------|-----------|
| **教育機能なし** | トレーニング・学習機能を持たないため、GAP-O1（体系的教育）は別途対応が必要 |
| **フィッシング演習なし** | シミュレーション機能がないため、GAP-H2（フィッシング対応力）は直接解決できない |
| **効果測定の難しさ** | 文化変革は長期的な取り組みであり、短期的なROI証明が難しい |
| **運用負荷** | ニュースフィードのキュレーション、Q&A回答、チャンピオン制度運営に継続的な人的リソースが必要 |
| **匿名性の課題** | 匿名報告の悪用リスク（虚偽報告、いたずら）への対策が必要 |
| **行動変容の間接性** | 報告や情報共有は「意識向上」には有効だが、直接的な「行動変容」（パスワード管理改善等）への効果は間接的 |
| **チャンピオンの負荷** | 通常業務に加えてチャンピオン活動を行うため、選出された従業員の負荷が増加 |

## 8. まとめ

案Cは、Gap分析で最重要課題Top 3に挙げられた「心理的安全性に基づく報告文化の醸成（GAP-C1）」に直接アプローチする唯一のソリューションである。
